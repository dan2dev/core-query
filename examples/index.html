core-query examples

Real use cases, one per page: open it, use it and read its source. Every page comes rendered by the server (ssr.mjs); from there the browser routes between them without reloading (app.mjs, layout.html).

The basics

  • Your first components

    Step by step, for beginners: write HTML once and reuse it, give it data, a list of it, slots, its own memory, a little JavaScript, shared calculations.

  • The to-do list of the 2017 thesis

    The original app: not one line of JavaScript in the page; the list is posted to the server on every change.

  • Components

    Tabs, a modal with <dialog>, notifications that animate in and out, a theme; a native accordion and popover.

  • Sign-up form

    Every kind of field (radio, checkboxes in an array, a multiple select, a range), errors once a field is left, a conditional field.

  • Chat

    Enter sends, tick() to scroll once the DOM is updated, an asynchronous answer from the bot.

Lists and data

  • TodoMVC

    A keyed list, the filter in the URL (route.hash), double-click editing (Enter saves, Esc cancels) in local state (data-state-*), localStorage.

  • Users table

    Accent-insensitive search, sorting by column, bulk selection, an active row, deletion; keyed rows in a <table>.

  • Kanban

    Nested keyed lists, drag and drop between columns, a draft per column in local state.

  • Async search

    Your own asynchronous code: debounce, cancelling the previous request, loading / error / empty / results, "load more".

  • Declarative search

    No JavaScript in the page: built-in functions, .debounce and .outside, a get request with loading / error, data-state-*, data-transition; the API and the first results come from ssr.mjs.

Whole applications

  • Shop

    Cards with data-use and slots, a cart with quantities, a coupon, shipping and totals; the cart is kept on the server.

  • Invoices

    A document editor over nested state: the invoice picked from a list, keyed lines that move and duplicate, every amount a template function, undo / redo and saving kept by app.on(), a print view.

  • Dashboard

    Charts drawn by the templates inside <svg>: lines with a crosshair (pointer or keyboard), sparklines, bars; filters that scope everything, a view derived from the data by app.on(), live updates.

  • Routes

    The router at its smallest: a page per route (routes/*.html) inside a layout of its own (routes/layout.html), parameters and query, the active link, a 404; the next pages from their template (fetched once, preloaded while the browser is idle) and the state the server sends as JSON.

  • Issue tracker

    A routed application on a server (tracker/*): filters, search and paging in the URL, an issue page with optimistic changes and comments, forms that post to a JSON API validated on the server, the server's 404 for what is not there.

How to run

pnpm build              # builds packages/core-query/dist
node examples/ssr.mjs   # → http://localhost:3000

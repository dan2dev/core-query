Your first components

A component is a piece of HTML you write once and use many times. In core-query it is plain HTML: a <template> and a few data-* attributes. You need no build step and no class. This page builds components one small step at a time. Each step shows its code first and the result below it, so you can try it right there.

On your own page, load core-query once, in the <head>: <script src="https://unpkg.com/core-query"></script>. It starts by itself once the page has loaded. Paste a step's HTML into your <body> and its JavaScript into a <script> placed after that tag. Some steps reuse a template from an earlier step: copy that template too. (This page runs the same JavaScript from first-components.mjs, and comes rendered by the server with that data.)

1. Write it once, use it many times

Put the HTML in a <template id="…">: the browser does not show it. Then every element with data-use="hello" gets a copy of it.

2. Give it data

The same card, two people. The data lives in JavaScript: CoreQuery.set('ana', {…}) (below) stores an object under the name ana, and a dotted name like ana.name is a path to a value inside it. data-let-user="ana" means: inside this card, user is ana, so user.name reads ana.name. The template only knows user, so it works for anyone. Try it: open the browser console and run CoreQuery.set('ana.name', 'Ann'). The first card changes. 

// The data of the page. Templates read it by path: "ana.name" is "Ana".
CoreQuery.set('ana', { name: 'Ana', job: 'Designer' })
CoreQuery.set('bia', { name: 'Bia', job: 'Developer' })

3. One per item of a list

Add data-for to the same element (it reuses the user-card template from step 2): one card per person. person in people names each item person, and data-let-user="person" hands it to the card as user. Click the button: the list grows, and a new card appears by itself. 

CoreQuery.set('people', [
  { name: 'Ana', job: 'Designer' },
  { name: 'Bia', job: 'Developer' },
])
CoreQuery.set('newcomer', { name: 'Caio', job: 'New here' })

6. Give it its own memory

Some things only matter to the component, like "is this answer open?". data-state-ui gives every copy its own ui, starting empty: here, each item of the list. Open one answer: the others stay closed. 

CoreQuery.set('faq', [
  { title: 'Do I need a build step?', answer: 'No: one script tag is enough.' },
  { title: 'Is it still HTML?', answer: 'Yes: a template and data-* attributes.' },
])

Two copies side by side, outside a list, would share one ui. Give each its own name and point ui at it: data-state-first data-let-ui="first", data-state-second data-let-ui="second".

7. Add some JavaScript

For what HTML cannot do alone, write a function with CoreQuery.component('clock', …) and put data-component="clock" on an element. The function gets the element and runs when the element appears; the function it returns runs when the element goes away. Here data-value ties the checkbox to showClock (true or false), and data-if keeps the paragraph only while it is true. Uncheck the box: the clock is removed and its timer stops.

It is .

CoreQuery.component('clock', (el) => {
  const show = () => (el.textContent = new Date().toLocaleTimeString())
  show()
  const timer = setInterval(show, 1000)
  return () => clearInterval(timer) // the element left the page
})
CoreQuery.set('showClock', true)

8. Connect JavaScript to the data

A modal <dialog> (dark backdrop, Esc closes it) opens only from JavaScript, with el.showModal(), so a component opens and closes it to match the data. On a component, data-value="modal" tells the function where its data is: it gets the element, that path ("modal") and the app. app.on(path, fn, { now: true }) calls fn with the value right away, then again each time it changes. Click the button, then close the dialog with its button or Esc.

I open and close when modal changes. Esc works too.

 
CoreQuery.component('dialog', (el, path, app) =>
  // app.on returns its own cleanup: return it, and it stops listening when the dialog goes away.
  app.on(path, (open) => (open ? el.open || el.showModal() : el.close()), { now: true }),
)
CoreQuery.set('modal', false)

9. Share calculations, and put components inside components

Templates have no + or *: a calculation is a function, built in like add (step 5) or your own, named with CoreQuery.fn, then used with |. Here every product card uses the stepper from step 5, and the total uses two functions.

Total: 

CoreQuery.fn({
  money: (n) => '$' + n.toFixed(2),
  total: (products) => products.reduce((sum, p) => sum + p.price * p.qty, 0),
})
CoreQuery.set('products', [
  { name: 'Coffee', price: 4.5, qty: 1, stock: 9 },
  { name: 'Bread', price: 2.25, qty: 2, stock: 4 },
])

With TypeScript

Optional: skip this while you use the script tag. If you install core-query with npm and a bundler, you create the app yourself and call app.mount() (the script tag does both for you), and TypeScript checks your components. The types come from your data, with no annotations: 

import { createApp, type Component } from 'core-query'

const app = createApp({ modal: false, order: { apples: 1, pears: 0 } })

// Annotate el and path to narrow them: open is a boolean.
app.component('dialog', (el: HTMLDialogElement, path: 'modal', a) =>
  a.on(path, (open) => (open ? el.open || el.showModal() : el.close()), { now: true }),
)
app.mount() // binds <body>: after registering components and functions

// A component for any app that has { volume: number }.
export const volume: Component<{ volume: number }> = (el, path: 'volume', a) =>
  a.on(path, (v) => (el.title = v + '%'))

app.set('order.apples', 2)
app.set('modal', 'yes') // error: a string is not a boolean
app.get('order.apple') // error: the paths there are 'order.apples' and 'order.pears'

Common mistakes

  1. The page stops working. The console says CoreQuery: no <template id="…">: the <template id> must be in the page, outside any data-if, data-for or other template, and the id must match data-use exactly.
  2. Mixed-case names. HTML makes attribute names lowercase: data-let-userName is the name username. Use lowercase names.
  3. data-let takes a path, not a calculation. data-let-x="price | money" is an error: pass the path (data-let-x="price") and use | money inside the template.
  4. The JavaScript does nothing. Call CoreQuery.component and CoreQuery.fn in a plain <script> placed after the core-query script tag, as here, so they run before core-query starts. "CoreQuery is not defined" in the console means your script runs before that tag. A data-component name with no CoreQuery.component is only a warning in the console; a function with no CoreQuery.fn (CoreQuery: unknown function "money") stops the page.
